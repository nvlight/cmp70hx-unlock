# Технический статус CMP 70HX Unlock

Актуально на 2026-10-11. Это каноническая техническая сводка; подробная
хронология сохранена в [`history/`](history/README.md).

## Что работает

| Область | Результат | Проверка |
|---|---|---|
| Compute | потолок issue-rate 1/32 снят, `pp512` ×11,25 | llama-bench, повторные прогоны |
| Render | `GFX_SPEED_SELECT=0x4`, Cyberpunk 2077 50 fps / 135 Вт | игровой бенчмарк и аппаратные логи |
| Частота | 1545 МГц под нагрузкой, без троттлинга | NVML/HWiNFO |
| Память | 8 ГБ, 256 бит, около 608 ГБ/с | CUDA properties и бенчмарки |
| Запуск | около 4,9 с вместо 218,1 с | `TIME ... final` и внешний замер |

Анлок выполняется UEFI-приложением до Windows. Через защищённую загрузку SEC2
открываются WPR2/PLM, затем выставляются SS0/SS1 и две необходимые render-маски.
После FLR управление возвращается прошивке, и Windows загружается без POST.

## Границы результата

- Карта сообщает 30 SM / 3840 CUDA cores; анлок это число не меняет.
- Read-only аппаратный снимок `grtopo-r0` объясняет эти 30 SM без остатка:
  GA104 сообщает 6 GPC по 4 TPC, но OTP disable-маска отключает GPC0/GPC1, а
  в GPC2 отключён один TPC. В GPC2..5 остаются `3+4+4+4=15` TPC, по 2 SM на
  TPC — ровно 30 SM. `gpc_defective=0`, но это не доказывает исправность
  отключённых блоков.
- В том же снимке `CTRL_OPT_GPC=0`, все шесть `CTRL_TPC=0`, все шесть
  `RECONF=0`, а PRE и POST совпадают. Значит, доступной дополнительной
  software/reconfiguration-маски для очистки не найдено и UEFI-анлок не
  меняет физическую GR-топологию.
- `FEAT_READOUT_0` bit 8 не является доказанным признаком PGRAPH: он равен нулю
  и на полноценно работающей RTX 3090. По нему нельзя называть GR «частичным».
- Раздельно проверяются: доступность D3D/Vulkan/CUDA API, полнота и скорость
  доступного 30-SM GR, физическая топология и отдельные RT/media-возможности.
  Работа API не доказывает наличие отключённых SM/L2/RT/NVENC/NVDEC.
- Для игр нужен драйвер с разрешённым render-путём для CMP, например
  `dartraiden/NVIDIA-patcher`.
- Три CPU-side GR-изменения из Linux 610.43.02 семантически перенесены в
  fail-closed эксперимент для Windows 616.92; методика и границы описаны в
  [`GR-DRIVER-PATCH.md`](GR-DRIVER-PATCH.md). R1–R3 загрузились без Code 43, но
  не изменили возможности или игровой результат: R3 дал 52,057 fps против
  R0=52,056 fps. Эти изменения дублируют действующий Windows render-патч и не
  требуются пользователю.
- Анлок волатилен: после POST его нужно выполнить снова.
- Поддерживается только CMP 70HX GA104 8 ГБ, PCI ID `10de:248a`.

Следующая незакрытая граница — read-only запрос native Linux NVIDIA RM:
`physGfxGpcMask`, `numGfxTpc`, глобальный порядок SM, ROP и ZCULL. Если RM
сообщит `numGfxTpc=15`, текущий render охватывает весь доступный OTP-предел;
получение 48 SM тогда потребовало бы обхода ранней fuse/OTP-тени, а не очистки
обычной runtime-маски. Методика: [`RM-TOPOLOGY.md`](RM-TOPOLOGY.md).

## PCIe Gen2

Серия E-A…E-P закрыла доступный путь отрицательно. Привилегированный V67 writer
работает, нужные маски и policy-регистры открываются, TLS=2 подтверждается на
обоих концах, Retrain Link запускается, но физический линк остаётся Gen1 x4.
Повтор по последовательности внешнего референса дал тот же результат.

Это не означает, что Gen2 физически невозможен; это означает, что доступные
этому проекту UEFI/BAR0/PCI-config способы исчерпаны. Повторять свипы масок,
Host2Jtag, LC2 mirror или серии retrain без нового механизма не следует.
