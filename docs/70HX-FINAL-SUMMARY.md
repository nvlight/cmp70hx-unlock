## 1. Статус

> ## АНЛОК РАБОТАЕТ — 2026-09-29 (раньше считалось
> ошибкой направлением)
>
> ```
> без анлока (чистый Windows)   pp512   201.85 t/s   tg16  32.50 t/s
> с анлоком (EFI + флешка)  pp512  2262.22 t/s   tg16 102.38 t/s
> ----------------------------------------------------------------------------
> эффект                                x11.25        x3.16
> ```
>
> Методика: `llama-bench -m llama-2-7b.Q4_0.gguf -ngl 99 -p 512 -n 16`,
> один и тот же модель, одна карта, запуск
> раза. Анлок волатилен, как и предполагает
> ранее для вычислительных тестов.
>
> **3D по-прежнему не менялся:** render test берет
> 75 Вт, Cyberpunk 9 FPS. Причина не в этом — графика у CMP
> заблокирована прошивкой, независимо от селекторов.
> Разбор — подробно в NEXT-STEPS §6.

## 2. Что доказано (не опровергнуто)

| # | Утверждение | Доказательство |
|---|---|---|
| 1 | FWSEC загружается в IMEM | `IVER empty=0 matched=0 occupied=9` — все 9 проб заняты |
| 2 | FWSEC исполняет команду FRTS | `WAIT *** WPR2 УСТАНОВЛЕН lo=0x01F7E000 hi=0x01F7EE00 после 0 ms` |
| 3 | Обе проверки драйвера пройдены | `OKCHK frtsErrCode=NONE`, `wpr2Hi != 0 OK`, `wpr2Lo == expected OK` |
| 4 | Регистры селекторов принимают запись | `STG selectors ... written OK` |
| 5 | Запись **переживает в Windows** | чтение `0xF682381C/20` через RWEverything: `0x88888888` / `0x00000008` — наши значения |
| 6 | Драйвер ОС не перезаписывает селекторы | то же чтение, проведено в сессии с Unlock |
| 7 | FLR селекторы не стирает | там же |
| 8 | `PLM` открывается | `STG PLM 0xFFFFFFFF ... OPEN` |

Исходный блокер проекта — «`WPR2` не защёлкивается» — **закрыт**. Это была
неверная расшифровка одного бита в команде DMA.

## 3. Что опровергнуто

| гипотеза | как |
|---|---|
| Подпись FWSEC невалидна | образ побайтово совпадает с репозиторным |
| В IMEM лежит подписанный картой FWSEC | IMEM после POST пуст |
| FRTS-регион надо заполнить заранее | маппер строит его сам |
| Кадровый буфер нужно заполнять напрямую | `0x1F7E00000` не адресуется DMA-движком GSP |
| `secure-доступ к IMEM закрыт` на 70HX | `0xDEAD5EC1` — отказ читать защищённое, а не отказ записи |
| `0x88888888` неверно для GA104 (гипотеза B) | запись в `0x0082380C` не удержалась → это отчётность |
| Значения селекторов есть в VBIOS | `0x88888888` — часть тест-паттерна ОЗУ `00 11 22 … FF` |
| Драйвер Windows перезаписывает селекторы | чтение из Windows: значения наши |
| `FLR` можно отменить | без него `WPR2` не возвращается в постовой вид, карта не инициализируется |

## 4. Три ошибки, которые стоили больше всего

Все три — одного класса: **показание принято за доказательство, не будучи им.**

1. **`is_unlocked()=1`** — функция перечитывает регистры, в которые код
   только что записал. Тавтология. Я на её основании написал «АНЛОК
   РАБОТАЕТ» в пяти местах документации.
2. **Молчание `FEATURE_READOUT`** — регистр документирован только как
   `ECC_DRAM` бит 16. Его немота ничего не значит ни в ту, ни в другую
   сторону.
3. **Объявление 3D-метрики непригодной** — README проекта прямо
   описывает патченный драйвер для игр. Не прочитал.

Общее правило, которое из этого следует: **критерий успеха обязан
измерять то, что изменяется при проверяемом событии, и перед его
выбором нужно прочитать документацию проекта целиком.**

## 5. Три исправления, которые дали результат

Каждое — одна строка, все — про чтение битов регистра по имени переменной
вместо описания поля:

| # | Исправление | Раздел |
|---|---|---|
| 1 | бит `IMEM` в `DMATRFCMD` (`0x604` → `0x614`) | KNOWN-ISSUES §36 |
| 2 | `g_fwsecImemSec = 1` (было `0`) | KNOWN-ISSUES §37 |
| 3 | fire-режим не входит при выключенном свипе | KNOWN-ISSUES §42 |

Плюс инфраструктурные, без которых правки нельзя было бы **обнаружить**:
очистка области лога каждый прогон, метки `STG`/`OKCHK`/`WAIT`/`FUSE` в лог
вместо экрана, проверка записи с readback.

## 7. Что остался

**Вычислительный анлок решён — этои пункт закрыт. Остальные
нерешённые вопросы — в§6 таблицы.

| старая проблемы | итог |
|---|---|
| 75 Вт / 9 FPS | не говорит о проверке анлока, а о тот факт о ней — см. §6 |
| 2262 вместо 3705 у эталонной 90HX | возможно, частично обусловано сильного толка (bendy2: 5 FBPA против 6, 10 LTC против 12). Не доказано |
| вторая карта | в системе `g_mcCount = 2`, обрабатывается карта 0 (`SINGLE_CARD_ONLY = 1`) — самый конкретный шаг в настящей системе |
| графика | требует патча GSP-RM, см. NEXT-STEPS §6 |
