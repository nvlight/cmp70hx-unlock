# E-A — гейт XP3G привилегированным писателем V67

**Дата постановки:** 2026-10-09. **Статус: ВЕРДИКТ `OPEN` — гейт открыт.**
Програн на железе 2026-10-09, сборка `xgate` md5 `8a71435595182b208bea7fea5e9fcfd2`,
686 080 байт, лог `out/usb-log-xgate.txt`, время прогона 7879 мс.

## 0. РЕЗУЛЬТАТ (2026-10-09)

```
XGATE phase0: gate 0x0008E1B0=0xFFFFFF8F ctrl 0x0008E1B4=0xFFFFFFCF
XGATE phase0: XP3G OVR0=0x00000000 VAL0=0x00000000 OVR3=0x00000000 VAL3=0x00000000
XGATE phase1: target  0x0008E1B0 <- 0xffffffff gave 0xFFFFFFFF OPEN (polls=81, recheck=0xFFFFFFFF, before=0xFFFFFF8F)
XGATE phase2: control 0x0008E1B4 <- 0xffffffff gave 0xFFFFFFFF OPEN (polls=81)
XGATE VERDICT: OPEN - gate opens privileged; XP3G_OVR0/VAL0 writable next; PORT-STATUS 1s needs rework
```

**Привилегированный писатель V67 открывает гейт XP3G в точный `0xFFFFFFFF`.**
С хоста он не открывается ни одной записью из 36 (§1r) — это разные писатели.

| | |
|---|---|
| до | `0xFFFFFF8F` |
| после | `0xFFFFFFFF` |
| polls | **81** — запись асинхронная, ~81 мс |
| recheck через 0,5 с | `0xFFFFFFFF` — **встало и не слетело** |
| контроль `0x8E1B4` | `0xFFFFFFFF`, polls **81** — тот же механизм |
| цена | 2 975 748 мкс = 26 % прогона |

Одинаковые `polls=81` у цели и контроля — признак одного и того же механизма,
а не везения.

### 0.1 Независимое подтверждение, чужеродным кодом

В дереве **уже был** дамп `GEN2M after-unlock`, к E-A отношения не имеющий.
Он печатает семейство `0x88FF4/0x88FF8/0x88AB4/0x8E1B0`; `!` = не изменилось
от POST-замеренного значения, `*` = изменилось.

| лог | сборка | POST | after-unlock |
|---|---|---|---|
| `usb-log-1008-235743` | `unlock_v3r` (рабочая) | `0x8E1B0=0xFFFFFF8F!` | `0x8E1B0=0xFFFFFF8F!` |
| `usb-log-sel0x8-notset` | `gfxsel_0x8_oracle` | `0x8E1B0=0xFFFFFF8F!` | `0x8E1B0=0xFFFFFF8F!` |
| `usb-log-pre-xgate` | `gfxsel_0x8_oracle` | `0x8E1B0=0xFFFFFF8F!` | `0x8E1B0=0xFFFFFF8F!` |
| **`usb-log-xgate`** | **`xgate` (E-A)** | `0x8E1B0=0xFFFFFF8F!` | **`0x8E1B0=0xFFFFFFFF*`** |

Во всех прошлых прогонах гейт оставался `0xFFFFFF8F` после анлока. В прогоне
E-A он `0xFFFFFFFF`, помечен `*`, и **соседи `0x88FF4` / `0x88FF8` / `0x88AB4`
остались закрыты** — то есть открылся именно `0x8E1B0`, а не «всё семейство
разом». Это подтверждение из существующего измерителя проекта, а не из нового
кода.

### 0.2 Регрессий нет

| строка приёмки | `usb-log-xgate` |
|---|---|
| `G2RMC render-masks top of iter 0: already open 0 of 2` | есть |

`STG reached selector block success=0 direct=0 early=0 gen2Fire=0` — **не
регрессия**: те же нули во всех четырёх прогонах выше, включая рабочий

Время: 7879 мс против 4870 / 4880 мс у рабочей сборки. Прирост **+2985 мс** —
это ровно цена двух ботер-циклов плюс два опроса по 81 мс и пауза 500 мс.
Цена предсказана заранее (~2,5 с) и совпала.

### 0.3 Что это меняет

§1s закрыл Gen2, потому что оставались два маршрута дороже результата:
реверс собственного V67 либо Windows-BYOVD. **Ни один не понадобился.**
Интерфейс блоба был уже известен проекту, требовалось сменить адрес.

Открытым остаётся ровно один вопрос, и он был назван в §1q до всяких
экспериментов: *«заливается ли policy set, когда гейт открыт»*. При
`0x8E1B0 = 0xFFFFFF8F` поле `XP3G_OVR0` (`0x8E110`) не вставало — это и был
провалившийся 7-й регистр из 7. Теперь гейт открыт, и следующий шаг (§5) —
проверить, что встают все семь.

**Линк в E-A не тронут.** Ни кика, ни TLS, ни ретрейна. Карта после прогона
осталась ровно в той же конфигурации, что и рабочая сборка, — Gen2 впереди.

## 1. Что именно проверяем

> Откроет ли **привилегированный** писатель V67 гейт `0x8E1B0` в точный
> `0xFFFFFFFF`, который с хоста не открывается **ни одной** записью из 36?

Это последний необходимый шаг к PCIe Gen2. Всё остальное по Gen2 уже измерено
и сделано — см. [`70HX-PORT-STATUS.md`](70HX-PORT-STATUS.md) §1o–§1s:

| факт | где |
|---|---|
| линк физически на Gen1: 3.343 GB/s, 83.6 % потолка Gen1 x16, `gen.current=1` под нагрузкой 11 из 11 | §1p |
| карта и слот способны Gen2 (`gen.max = 2`) — потолок не кремниевый | §1p |
| с хоста **не открывается ни одна маска из 36** — три прохода, ноль | §1r |
| привилегированный писатель есть, это V67 на RISC-V ядре SEC2 | §1q |
| 6 из 7 регистров политики xrip пишутся с хоста, седьмой (`XP3G_OVR0`) заперт гейтом `0x8E1B0 = 0xFFFFFF8F` | §1q |
| Gen2 закрыт по решению пользователя: оставались реверс V67 либо Windows-BYOVD | §1s |

## 2. Почему это НЕ повторение §1q / §1r

Отрицательный результат §1q/§1r честный, но он про **другого** писателя.
Там били `mmio_write32` **с хоста**, а маска и *есть* защита от такой записи —
вывод «0 из 36» верен для хоста и ничего не говорит о V67.

§1r это прямо оговаривает:

> *Это окончательно закрывает путь «открыть маску с хоста, потом писать
> политику». Одновременно это **не** закрывает Gen2: у нас уже есть
> привилегированный исполнитель (V67 открывает PLM), вопрос только в том,
> что именно он пишет.*

E-A — это ответ на «что именно он пишет», для одного адреса.

## 3. Примитив уже готов. Реверс блоба не требуется

V67 — **параметризованный** писатель, не непрозрачный кусок:

```
pv = payload+0xf948  ->  значение
pa = payload+0xf960  ->  адрес
```

Это зафиксировано в проекте двумя независимыми способами:

* комментарий `src/unlock_v2.c:5553-5554` (в коде, не в документации);
* работающие вызовы в дереве —
  `pcie_gen_unlock_debug()` пишет так же в `PCIE_FUSE_OVERRIDE` (`0x823810`),
  а `ftp_booter_write()` вообще параметризована как `write(addr, want, &polls)`.

Значит §1s указывает на более дорогой маршрут, чем нужно: **интерфейс блоба
проекту уже известен**, меняется только адрес.

### 3.1 Гейт уже есть в таблице

`0x8E1B0` с целевым значением `0xFFFFFFFF` **уже присутствует** в таблице
`g_rj16[]` (`src/unlock_v2.c:2471`):

```c
{0x00088ab4U,0xffffffffU},{0x0008e1b0U,0xffffffffU},{0x0008e1b4U,0xffffffffU},
```

Свип по `g_rj16` уже умеет писать эту запись привилегированно
(`*pv = g_rj16[i].val; *pa = g_rj16[i].addr; booter_load_v67(...)`).
Но свип выключен (`g_gen2Enable = FALSE`, `g_gen2Fire = FALSE`), и v3n/v3r
вырезали gen2-код.

**E-A намеренно НЕ включает свип целиком.** Причина — ловушка, которую надо
назвать, чтобы её не повторили: критерий завершения свипа требует точного `FF`
**по всем** записям таблицы, а

* `0x8E1DC` документирован как RO и точного `FF` не держит
  (`REGISTERS.md`, «НЕ держит точный FF — семейство живое/статусное»);
* блок OPTB `0x8200d0..0x8200f4` исключён (записи валят гостя в ресет, прогоны
  29–31), `0x88084` исключён (speed-ниббл живой, следует за линком).

То есть `done` не сбрасывается никогда, и включение свипа сожжёт 3 полных
прохода впустую. E-A делает **два точечных выстрела** вместо этого.

## 4. Фазы и почему они именно такие

Риск растёт строго по фазам; фаза 0 только на чтение идёт первой, чтобы даже
жёсткое зависание в фазе 1 оставило дамп в логе на флешке.

| фаза | что | риск |
|---|---|---|
| **0** | ТОЛЬКО ЧТЕНИЕ: `0x8E1B0..BC`, семейство, `XP3G` `OVR0`/`VAL0`/`OVR3`/`VAL3` | нулевой |
| **1** | **ЦЕЛЬ**: `0x8E1B0 ← 0xFFFFFFFF` привилегированно | снятие защиты с записи |
| **2** | **КОНТРОЛЬ**: `0x8E1B4 ← 0xFFFFFFFF`, тот же код, свой FLR-цикл | то же |

**Живой линк блок не трогает.** Нет ни кика `0x8872C`, ни TLS, ни ретрейна, ни
записей политики PCIe. Пишется только регистр-маска — то есть снимается защита
с записи, и ни одного функционального бита. Это ровно то, что §1q объявил
заранее перед шагом 1b.

**Цена:** два полных ботер-цикла, ~2,5 с к прогону (4,9 с).

Ограничение ботера — третий выстрел в одном состоянии SEC2 не работает
(v3.18), поэтому между фазами 1 и 2 обязателен свой FLR-цикл, как в
`ftp_booter_write()`.

### 4.1 Почему контроль обязателен

[`70HX-FINAL-SUMMARY.md`](70HX-FINAL-SUMMARY.md) §4: **«показание принято за
доказательство, не будучи им»** — три самые дорогие ошибки проекта были именно
такого рода.

Отрицательный результат фазы 1 сам по себе не значит ничего: он не отличает
«гейт особенный» от «механизм в этом прогоне не выстрелил». `0x8E1B4` — сосед
по тому же семейству `0x8E1B0..F0`, с тем же стоковым значением, и открывается
тем же кодом. Разбор только пары «цель + контроль»:

| контроль `0x8E1B4` | цель `0x8E1B0` | что это значит |
|---|---|---|
| `OPEN` | `OPEN` | **гейт открыт.** §1s пересмотреть, Gen2 жив, идти в §5 |
| `OPEN` | `NOT OPEN` | гейт особенный, не открывается. Отрицательный результат **заслуженный** |
| `NOT OPEN` | — | **результат фазы 1 НЕДЕЙСТВИТЕЛЕН.** Закрывать Gen2 по нему нельзя, надо разбираться с механикой |

## 4a. ЭКСПЕРИМЕНТ E-B — ПОЛИТИКА ЗАЛИВАЕТСЯ. РЕЗУЛЬТАТ

Прогон 2026-10-09, сборка `xgate2` md5 `9832745e50ee02cff08ec8d0c8cc5c45`,
688 640 байт, лог `out/usb-log-xg2.txt`, 7849 мс.

```
XGPOL precondition: XP3G gate 0x0008e1b0 = 0xFFFFFFFF OPEN
XGPOL XP3G_OVR0 0x0008E110 before=0x00000000 want=0x00000001 CHANGE
XGPOL XP3G_OVR0 0x0008E110 wrote 0x00000001 got 0x00000001 STUCK
XGPOL summary: 5 of 5 changed fields stuck (2 NOOP not counted)
XGPOL VERDICT: POLICY-OK
```

**Вопрос, который §1q назвал до всяких экспериментов, закрыт: при открытом
гейте policy set заливается.**

| было (§1q, гейт закрыт) | стало (E-B, гейт открыт) |
|---|---|
| **6 из 7** полей вставали | **5 из 5** значимых встают |
| `XP3G_OVR0` (`0x8E110`) — `*** НЕ ВСТАЛО ***` | `XP3G_OVR0` — `STUCK` |

Продавленное в §1q поле — то самое, ради которого Gen2 был закрыт в §1s.

### 4a.1 Почему 5, а не 7 — и почему это важно

Два поля помечены `NOOP` и **в счёт пройденных не идут**:

| поле | before | want | почему NOOP |
|---|---|---|---|
| `XP3G_VAL0` `0x8E120` | `0x00000000` | `0x00000000` | уже было нулём |
| `PL_LINK_RATE` `0x8C1C0` | `0x00140000` | `0x00140000` | **изменилось после E-A**, в §1q было `0x00060000` |

Это ровно та ловушка, что описана в `70HX-FINAL-SUMMARY` §4, ошибка №1:
«`is_unlocked()=1` — функция перечитывает регистры, в которые код только что
записал. Тавтология». Поле, у которого цель совпала с «до», ничего не доказывает
и по построению всегда даёт «успех». Без защиты от этого E-B отчитался бы
«7 из 7» с двумя фиктивными проходами.

### 4a.2 Линк не тронут

```
XGPOL link BEFORE: LNKSTA=0x11010040 speed=1 width=4
XGPOL link AFTER : LNKSTA=0x11010040 speed=1 width=4
```

Побитово идентично, `speed=1` (Gen1) — как и был.

### 4a.3 Побочное наблюдение, которое стоит держать в голове

В дампе `GEN2M after-unlock` этого прогона впервые видно **семейство открытым
частично**, а не «три маски, которые всегда были открыты»:

```
[ 0.. 3] 0x00823804=0xFFFFFFFF* 0x00088FE8=0xFFFFFFCF! 0x00088FEC=0xFFFFFFCF! 0x00088FF0=0xFFFFFFCF!
[ 4.. 7] 0x00088FF4=0xFFFFFF8F! 0x00088FF8=0xFFFFFF8F! 0x00088AB4=0xFFFFFF8F! 0x0008E1B0=0xFFFFFFFF*
[ 8..11] 0x0008E1B4=0xFFFFFFFF* 0x0008E1B8=0xFFFFFFCF! 0x0008E1BC=0xFFFFFFCF! 0x0008E1C0=0xFFFFFFCF!
[16..19] 0x0008E1D4=0xFFFFFFFF* ... 0x0008E1DC=0xFFFFFF8F!
[20..23] ... 0x0008E1F0=0xFFFFFFFF*
```

`*` теперь стоит на `0x8E1B0`, `0x8E1B4` **и** `0x8E1F0` — то есть привилегированный
писатель меняет состояние, которого не менял ни один предыдущий прогон, и
соседние регистры семейства остаются закрытыми. Это независимая проверка
адресности: пишется ровно запрошенный адрес.

### 4a.4 Регрессий нет

`already open 0 of 2` / `1 of 2` без `iter 2`, `GFX gates open 2 of 2`,
`GFX_SPEED_SELECT=0x00000004 SET`, `END ss0=0x88888888 ss1=0x00000008
PLM=0xFFFFFFFF`, маркер конца лога на месте.

Время: 7849 мс. E-B добавил **31 мкс** — семь MMIO-записей, как и ожидалось.
Время прогона целиком определяется E-A (2 972 568 мкс, 26 %).

### 4a.5 Что осталось

Ровно одно действие, и оно **впервые трогает живой линк**:

| шаг | что | чем | где брать |
|---|---|---|---|
| 1 | кик LTSSM **последним**, после всех записей | BAR0 `0x8872C = 6` | уже есть в дереве |
| 2 | `TLS = 2` на GPU | PCI config `cap+0x30.w` | §1p ошибка 2: через BAR0 `0x880A8` отбрасывается |
| 3 | `TLS = 2` на root port | PCI config `cap+0x30.w` | там же |
| 4 | retrain | root port `+0x10.w \|= 0x20` | §1p |

Известные границы, чтобы не тратить время:

* `LINK_CAP` (`0x88084`) **не писать** — xrip его не пишет, и `speed`-ниббл
  живой: следует за фактическим линком, кремний клампит Gen3
  (`write 03 → readback 02`, `REGISTERS.md`).
* Gen3/Gen4 целью не является: кламп тот же, и на 40HX эта граница исследована
  до конца (`PCIE_GEN3_CMP40HX_RESEARCH.md`).
* `TLS` через BAR0 не работает под живым GSP — только PCI config.

**Критерий Gen2 — единственный честный:** `src/tools/pcie-bw.py` даёт
**> 5,5 GB/s** против нынешних 3,343. `nvidia-smi --query-gpu=pcie.link.gen.current`
критерием **не является** — это downshift в простое (§1p шаг 0.1).

Риск шага 1 — единственный в проекте, где возможна потеря `nvidia-smi`:
на 40HX Link Disable отрывал GSP/RM, но здесь шаг нормальный (ре-train
без Disable) и применяется на живом линке. Откат — перезагрузка с флешки.

## 5. Если вердикт `OPEN` — порядок Gen2 (заменено разделом 4a)

Ничего из этого в E-A нет. Записано, чтобы следующий шаг не переоткрывал
сделанное. Поля и значения — из xrip/§1q, порядок важен.

| шаг | что | чем |
|---|---|---|
| 1 | `XP3G_OVR0 = 1`, `XP3G_VAL0 = 0` | BAR0 `0x8E110` / `0x8E120` |
| 2 | `LINK_CONFIG_0` `MAX_RATE[19:18] = 2` | BAR0 `0x8C040` |
| 3 | `PL_LINK_RATE = 0x00040000` | BAR0 `0x8C1C0` |
| 4 | `PRIV_MISC_1`: биты 11,13 = 1; 12,14 = 0 | BAR0 `0x8841C` |
| 5 | `VSEC_HIERARCHY`: бит 12 = 0 | BAR0 `0x88610` |
| 6 | `CYA_0`: бит 2 = 0 | BAR0 `0x8C2C0` |
| 7 | кик LTSSM **последним** | BAR0 `0x8872C = 6` |
| 8 | `TLS = 2` на GPU **и** на root port | PCI config `cap+0x30.w` |
| 9 | retrain | root port `+0x10.w \|= 0x20` |

**Важно, измерено ранее:** `LC2 TLS` через BAR0 (`0x880A8`) под живым GSP
**отбрасывается** — TLS ставится только через PCI config. §1p шаг 0.5, ошибка 2.

**Единственный честный критерий Gen2** — физическая полоса, а не
`nvidia-smi --query-gpu=pcie.link.gen.current` (это downshift в простое, §1p
шаг 0.1):

```
src/tools/pcie-bw.py  ->  > 5,5 GB/s     (против нынешних 3,343)
```

Gen3/Gen4 целью не является: `LINK_CAP` клампится кремнием, замер «write 03 →
readback 02» (`REGISTERS.md`), и на 40HX тот же барьер исследован до конца.

```powershell
out\reset-stick-log.ps1      # стереть СТАРЫЙ лог — иначе приёмка примет чужой
# прошить src/xgate.efi на флешку как EFI\BOOT\BOOTX64.EFI
# перезагрузка, F12, выбрать флешку
out\pull-log.ps1 -Tag <метка>
```

## 7. Приёмка

Строки ASCII в логе (`ulogf` транслитерирует всё вне `0x20..0x7E`, поэтому
кириллицы в логе нет):

```
XGATE phase0: gate 0x0008e1b0=0x........ ctrl 0x0008e1b4=0x........
XGATE phase1: target 0x0008e1b0 <- 0xffffffff gave 0x........ OPEN|NOT OPEN (polls=N, recheck=0x........, before=0x........)
XGATE phase2: control 0x0008e1b4 <- 0xffffffff gave 0x........ OPEN|NOT OPEN (polls=N)
XGATE VERDICT: OPEN | GATE-ONLY-LOCKED | INCONCLUSIVE
XGATE === E-A done: xg ===
```

`recheck` в фазе 1 отделяет «не встало» от «встало и слетело» (повторное
чтение через 0,5 с).

**Плюс обычная приёмка обязана сохраниться** (ничего не должно сломаться):

```
G2RMC render-masks top of iter 0: already open 0 of 2
G2RMC render-masks top of iter 1: already open 1 of 2
G2GFX step1-GFX_SEL ORDER A (GFX after SS): GFX_SPEED_SELECT=0x00000004 SET
END    ss0=0x88888888 ss1=0x00000008 PLM=0xFFFFFFFF
```

Отдельно: `pp512` / `tg16` не должны просесть (анлок ×11,25),
`×11.25` — проверка, что блок не сломал анлок.

## 9. Откат

```bash
git revert <коммит>
cd src && BLOBS="$PWD/blobs" bash build.sh   # обязан дать откатный md5
```

`xp3g_gate_v67_probe` / `xg_v67_write` целиком внутри `#ifdef XP3G_GATE_V67`,
поэтому revert восстанавливает релизный бинарь побайтово (см. §8).

## 10. Куда это ведёт

E-A — первый из трёх шагов нового плана. Он не самоцель, а **включатель**:

1. **E-A** (этот документ) — открывается ли гейт → оживает ли Gen2.
2. **Батчинг привилегированных записей.** Сейчас одна запись = один FLR +
   ботер = 1,24 с, поэтому рендер-цикл это 2 обязательные итерации (2 490 мс из
   4 894). Блоб 64 КБ использует **два** слова; если в ROP-хвосте есть вторая
   пара «значение/адрес», батчинг — это сдвиг указателей, а не исследование.
   Рецепт цепочки целиком (включая стек-пивот на второй стек, освобождение
   ACR-мьютекса и `booterCleanupAndHalt`) есть в исходниках:
   `Cyridd/cmpunlocker`, `0001-cmp40hx-unlock.patch` — та же конструкция
   canary-ROP, тот же блоб, слоты в той же области `0xF9xx`.
3. **Host2Jtag** — снятие последнего потолка. В списке разблокировок
   `amoghmunikote/cmpunlocker` (CMP 170HX) значится как рабочее. Нужен потому,
   что каждый оставшийся неоткрытый вопрос упирается в «регистр недоступен»,
   а не в «значение неизвестно».

Детали и обоснование — в разделе плана, обсуждавшемся 2026-10-09.

## 11. Что E-A НЕ делает

* Не трогает линк, TLS, ретрейн, политику PCIe — ни одного функционального бита.
* Не меняет релизную сборку (доказано побайтово, §8).
* Не включает свип `g_rj16` целиком — из-за ловушки с `done`, §3.1.
* Не трогает VBIOS и не прошивает ничего.
* Не претендует на Gen3/Gen4 — там кремниевый кламп, измерено.
