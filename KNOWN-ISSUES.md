# Известные ограничения

Актуально на 2026-10-11. Полный прежний журнал из 51 раздела сохранён в
[`docs/history/KNOWN-ISSUES.md`](docs/history/KNOWN-ISSUES.md).

## 1. Поддерживается только CMP 70HX

Профиль рассчитан на GA104, 8 ГБ и PCI ID `10de:248a`. Альтернативные device ID
в перечислителе — историческая латентная опасность, а не обещание поддержки.
Не запускайте этот профиль на 10-ГБ GA102/CMP 90HX.

## 2. Secure Boot и POST

EFI-файл не подписан: Secure Boot должен быть выключен. CSM и Fast Boot также
должны быть выключены. Полный reboot/POST сбрасывает анлок; после него загрузка
с USB нужна снова.

## 3. Драйвер для графики

Стоковый NVIDIA-драйвер отдельно блокирует render для CMP. Compute-анлок от
этого не страдает, но для игр нужен патченный драйвер. Работающий compute не
доказывает, что render-путь открыт.

## 4. Физическая конфигурация не расширена

`GFX_SPEED_SELECT=0x4` даёт 50 fps / 135 Вт в зафиксированном тесте, но карта
остаётся на 30 SM / 3840 cores и 2 МБ L2. Ни запись заявленного числа SM, ни
WPR metadata flags, ни доступные mask/fuse-регистры не увеличили конфигурацию.
Это не означает «частичный PGRAPH»: прежняя трактовка `FEAT_READOUT_0.bit8`
оказалась недостоверной. Полнота доступного GR требует отдельного API и A/B-
теста; RT и media-блоки не выводятся из результата raster-бенчмарка.
Драйверные варианты R1–R3 не ускорили Cyberpunk относительно R0: полный R3
дал 52,057 fps против R0=52,056 fps. Перенесённые Linux GR-изменения дублируют
действующий Windows render-патч и не расширяют физическую конфигурацию.

## 5. PCIe остаётся Gen1 x4

Серия E-A…E-P открыла доступные гейты, выставила TLS=2 с обеих сторон и
выполнила повторные retrain, однако LNKSTA остался 2,5 GT/s. Доступный путь
считается закрытым до появления нового механизма уровня BootROM/FPGA либо
другого документированного интерфейса.

## 6. Лог может принадлежать предыдущей загрузке

Образ 256 МиБ не покрывает область лога на LBA 4 000 000. Перед приёмочным
прогоном обязательно запускайте `out/reset-stick-log.ps1`. Единственный признак
полного запуска — `END   ---- end of log ----`.

## 7. Сборка зависит от toolchain

Эталон воспроизводится GCC 12. GCC 15 создаёт другой PE. `build.sh` хранится с
CRLF, поэтому в Linux может требоваться временная LF-копия рядом с исходником.

## 42.10. Финальный WPR2 readback

Финальный `WPR2_LO` может отличаться от промежуточного ожидаемого значения на
`0xD1000`. Это штатное состояние GSP после успешного цикла. Критичен провал в
строке `FLRX`, а не слово `UNEXPECTED` в итоговой диагностической строке.

## 47. Побочная запись `0x00823818`

Значение может меняться в ходе открытия SS-страницы. На проверенных прогонах
это не вызвало функционального дефекта, но регистр нельзя использовать как
самостоятельный критерий успеха.

## 50. Откат — это git-тег

Отдельного compute-only rollback-файла нет. Рабочий `unlock_v3r.efi` является
и загрузчиком, и точкой возврата. Текущий проверенный якорь —
`rollback-2026-10-10`, MD5 `3C076AF7CF7C2BDA65FDA01F7678982C`.

## 51. Находки по внешнему референсу

### 51.1. BAR0 `0xFFFFFFFF` неоднозначен

Это может быть открытая маска или мёртвый/недоступный BAR0. Проверяйте
положительные контрольные регистры до интерпретации.

### 51.2. Предусловие V67 canary

Render-цикл должен предшествовать блоку селекторов; маркер `G2RCC` обязателен в
релизном бинарнике и проверяется `flash-build.ps1`.

### 51.5. PCIe capability offsets

Capability Pointer читается по `0x34`. `LNKCTL2` расположен по `cap+0x30`, а
`LNKCAP2` по `cap+0x2C` read-only. Нельзя переносить ошибочный офсет внешнего
скрипта. Серия Gen2 после этого исправления всё равно закончилась Gen1 x4.
