#  Разблокировка CMP 70HX

Полная разблокировка вычислительной и частично графической мощи **NVIDIA CMP 70HX** (GA104, 8 ГБ, PCI ID `10de:248a`) в Windows — с помощью обычной флешки, EFI-загрузчика и **без перезагрузок**.

Анлок выполняется **до загрузки ОС**, поэтому Windows просто стартует с уже полностью открытой картой.



**Что именно разблокировано на 70HX** ([подробно, п. 1k](docs/70HX-PORT-STATUS.md)):

| | состояние |
|---|---|
| вычисления | **разблокированы**, ×11,25 по `pp512` |
| механизм блокировки | **потолок issue-rate 1/32** на FP32 и DP4A, снят полностью |
| периферийные issue-rate | **на 91–99,8 % от архитектурного пика**, остаточных лимитов нет |
| частота | 1545 MHz под нагрузкой, троттлинга нет, потолком не является |
| ядра | 3840 CUDA core из 6144; **A/B сделан — анлок это число не меняет** |
| графика | **разблокирована частично**: `GFX_SPEED_SELECT = 0x4`, Cyberpunk 2077 **50 fps / 135 Вт**. `FEAT_READOUT_0` бит 8 (PGRAPH) остаётся 0 — это урезанный кристалл, а не не открытая маска |
| время прогона | **≈ 4,9 с** (релиз 1.0.0, v3.52) |

## Как работает анлок

1. **Предзагрузка.** Загрузчик Windows (`bootmgfw.efi`) читается в ОЗУ через сырой блочный ввод-вывод собственным FAT32-парсером. (UEFI SimpleFileSystem не используется — на некоторых платах AMI он вешает систему.)
2. **Анлок.** Приложение проводит SEC2 (Falcon) видеокарты через её защищённую загрузку:
   - снимает защиту записи памяти (WPR2),
   - загружает подписанный «канареечный» пейлоад (V67) в ботер SEC2,
   - открывает защищённый режим GPU (PLM),
   - прописывает compute-селекторы (SS0/SS1) и маски рендера.
3. **Ресет.** Function Level Reset (FLR) сбрасывает защёлкнутые регистры защиты — селекторы его переживают.
4. **Загрузка.** Приложение возвращается в прошивку без POST, и Windows грузится с уже разлоченной картой. **Перезагрузки нет** — POST сбросил бы анлок.

Сам эксплойт: подписанный ботер SEC2 содержит баг stack-canary (Jon Pry, *"A Canary in the Crypto Mine"*). При проверке нашего увеличенного 64-КБ «подписанта» исполнение уходит в ROP-цепочку, которая выполняет произвольные привилегированные записи в регистры — включая открытие PLM.

## Требования

| | |
|---|---|
| Карта | NVIDIA CMP 70HX, PCI ID `10de:248a` |
| Windows | на GPT-диске с EFI-разделом |
| Above 4G Decoding | **Enabled** |
| Secure Boot | **Disabled** — загрузчик не подписан |
| CSM | **Disabled** (только UEFI) — иначе флешка не загрузится |
| Fast Boot | **Disabled** — иначе UEFI-этап пропускается и флешка не появится в boot-меню |
| Resizable BAR | **Auto/Enabled** — дополняет Above 4G |
| Флешка | **от 512 МБ**; чтобы писался лог прогона — **от 4 ГБ** |

Плата должна быть UEFI с boot-меню (обычно F12, F8 или Del).

## Релиз 1.0.0

Установка стала процессом для обычного человека: скачали образ, записали на
флешку через Rufus, выбрали её в boot-меню. Никакой разметки, форматирования и
копирования файлов вручную.

Образ — 256 МиБ, схема MBR + FAT32 (тип раздела `0xEF`) и загрузчик в
`EFI\BOOT\BOOTX64.EFI`.

**Установка:**

1. Скачать `cmp70hx-unlock-1.0.0.img.gz` и `SHA256SUMS` со страницы
   [Releases](https://github.com/nvlight/cmp70hx-unlock/releases).
2. Распаковать `cmp70hx-unlock-1.0.0.img.gz` (Проводник Windows или 7-Zip) —
   получится `cmp70hx-unlock-1.0.0.img`. В [Rufus](https://rufus.ie/) выбрать
   этот `.img` и нажать «Начать».
3. Сверить хэш с файлом `SHA256SUMS`:
   ```powershell
   Get-FileHash .\cmp70hx-unlock-1.0.0.img.gz -Algorithm SHA256
   ```
   (на Linux: `sha256sum -c SHA256SUMS`)
4. Перезагрузка, **F12** (или клавиша boot-меню вашей платы), выбрать флешку.
5. Анлок выполнится сам, Windows загрузится на полной мощности.
6. *(Только для игр)* Установить патченный драйвер из
   [NVIDIA-patcher](https://github.com/dartraiden/NVIDIA-patcher).

### Что на флешке

| файл | |
|---|---|
| `EFI\BOOT\BOOTX64.EFI` | загрузчик, md5 `C68878AFAFD0D2D246D2E25C5ACBD888` |
| `VERSION.txt` | версия, коммит, md5 загрузчика |
| `README.txt` | инструкция для того, кто читает флешку с другого компьютера |

`gsp_ga10x.bin` на флешке **не нужен**: с v3.52 загрузчик его не читает.

### Про хэши

**md5 и sha256 самого `.img` меняются при каждой пересборке** — внутри FAT32
есть случайный serial тома и метки времени. Постоянная величина одна: **md5
загрузчика `C68878AFAFD0D2D246D2E25C5ACBD888`**. Он же записан в `VERSION.txt`
на флешке, так что версию можно опознать, не сверяясь с интернетом.
`SHA256SUMS` относится к конкретному приложенному файлу и годится для
проверки именно его.

### Если флешка не появилась в Проводнике

Это не поломка. Раздел в MBR имеет тип `0xEF` (ESP) — он обязателен, без
него прошивка не покажет флешку как UEFI-загрузочную, — а Windows такие тома
не монтирует автоматически. В «Диспетчере дисков» флешка есть, буквы просто
нет. Ни загрузке, ни снятию лога буква не требуется. Назначить её вручную:

```powershell
git clone https://github.com/nvlight/cmp70hx-unlock
cd cmp70hx-unlock
powershell -ExecutionPolicy Bypass -File out\assign-stick-letter.ps1
```

### Если прошивка не показывает флешку в boot-меню

Проверьте в BIOS, что **CSM выключен** и **Fast Boot выключен** — при CSM
флешка не загрузится вовсе, а при Fast Boot UEFI-этап пропускается и флешка
не появится в списке. Дальше: зачастую виноват тип раздела в MBR, должен быть
`0xEF`, а не `0x0C` ([docs/GOTCHAS.md](docs/GOTCHAS.md)). Некоторые AMI-прошивки
требуют также, чтобы носитель не содержал старый backup-GPT в хвосте — тогда
сначала зачистите флешку целиком (`diskpart clean`) и запишите образ заново.


### Для разработчика: снятие лога и проверка записи

Обычной установке не требуется. Нужно только когда вы хотите убедиться, что на
флешке именно тот загрузчик, что собран:

```powershell
out\reset-stick-log.ps1                    # стереть СТАРЫЙ лог (см. ниже)
out\pull-log.ps1 -Tag <метка>
out\verify-image.ps1 -CompareOnly
```

`reset-stick-log.ps1` нужен по конкретной причине: образ 256 Миб не покрывает
область лога (LBA 4 000 000), поэтому там остаётся лог **предыдущей**
загрузки. Если пропустить сброс и снять лог до загрузки с новой флешки,
`pull-log.ps1` прочитает старый — с маркером `END` и «успехом» — и приёмка
объявит успех там, где приложение даже не стартовало.

**Сборка образа из исходников** (нужны Windows-права администратора):

```powershell
powershell -ExecutionPolicy Bypass -File out\make-image.ps1     # -> dist\*.img, *.gz, SHA256SUMS
powershell -ExecutionPolicy Bypass -File out\verify-image.ps1   # проверка образа, код 0 = годен
```

Подробности — в [BUILDING.md](BUILDING.md) §4.

> **Публикуемость образа.** Проверка `verify-image.ps1` доказывает, что в образе
> лежит правильный загрузчик и правильная геометрия раздела. Она **не** может
> доказать две вещи — что конкретная прошивка покажет флешку в boot-меню и что
> карта реально разлочится. Это проверяется только загрузкой с флешки на
> машине. Поэтому публикация релиза идёт после прогона на железе (BUILDING §6.2a).

**Сборка образа из исходников** (нужны Windows-права администратора):

### Повторный запуск после перезагрузки

Анлок **волатилен**: полный ребут (POST) сбрасывает GPU. Чтобы разблокировать
снова — просто загрузитесь с флешки ещё раз и дайте ей передать управление
Windows. Всё. Измеренное время одного прогона — **4894 мс**.

## Приёмка сборки — что должно быть в логе

Лог читается хостовым `out\pull-log.ps1` (сырые секторы флешки, не serial).
Проверяется **внутри бинарника** до записи на флешку — BUILDING §6.1.

Сборка принята, если в логе есть **все** эти строки:

Лог пишется `ulogf()`, который транслитерирует всё вне `0x20..0x7E` в `?`
(`docs/LOGGING.md` §3), поэтому в нём **нет кириллицы** — искомые строки
ASCII. Приводим устойчивые фрагменты (точные строки длиннее и меняются от
сборки к сборке; `out/verify-log.ps1` проверяет их на соответствие):

```
G2RMK  render-masks pass1 0x00823800 became 0xFFFFFFFF OPEN
G2RMK  render-masks pass1 0x00823B04 became 0xFFFFFFFF OPEN
G2RMC  render-masks top of iter 0: already open 0 of 2
G2RMC  render-masks top of iter 1: already open 1 of 2
G2GFX  step1-GFX_SEL ORDER A (GFX after SS): GFX_SPEED_SELECT=0x00000004 SET
G2SUM  ... readback 0x00000004 OK
END    ss0=0x88888888 ss1=0x00000008 PLM=0xFFFFFFFF
END    ---- end of log ----
```

И **ни одной** из этих:

| Плохая строка | Что означает |
|---|---|
| `already open` не равно номеру итерации | цикл не открыл маску, рендер-разблокировка сломалась |
| `dbg=0x007E0009` | ядро стартует и гибнет, DMA не доставила |
| `FLRX  WPR2 restored … *** DID NOT HOLD ***` | ботер не защёлкнул WPR2 (строка `FLRX`, а не `G2RMK`/`END`) |
| отсутствие маркера `END` | лог оборвался; обрыв на границе сектора = не сброшен последний буфер |

> **Маркер числа масок в v3.52 — `G2RMC … already open N of 2`**, а не
> `G2RMS TOTAL: XVE window open 8 of 8`, как было в v3.39. Окно XVE убрано
> в v3.40, и проверять надо тот счётчик, который печатает текущая сборка.
>
> **Про `*** UNEXPECTED ***` на WPR2 — это не брак.** В строках `G2RMS … TOTAL`
> и `END` штатно печатается `WPR2=0x01EAD000/0x01F7EE00`: `WPR2_LO` в финале
> читается со сдвигом `0xD1000` от `0x01F7E000`, тогда как ожидаемое значение
> `0x01F7E000` встаёт корректно в середине цикла (`WAIT *** WPR2 ESTABLISHED
> … after 11 ms ***`). Состояние разобрано и **не является помехой** анлоку —
> см. `KNOWN-ISSUES.md` §42.10 и `docs/70HX-PORT-STATUS.md` §9. Признаком
> брака считайте `UNEXPECTED` в строке `FLRX`, а не в финальных.

Отдельно сверяется **время прогона** — строка `TIME t=…ms final: before return
to firmware` плюс замер секундомером. Расхождение больше 5 с означает, что
часть работы не попала в счётчик.


## Сборка из исходников

```bash
git clone https://github.com/nvlight/cmp70hx-unlock
cd cmp70hx-unlock/src
BLOBS=/путь/к/блобам bash build.sh   # единственная цель: CMP 70HX / GA104
```

Из собранного `unlock_v3r.efi` собирается релизный образ флешки:

```powershell
powershell -ExecutionPolicy Bypass -File out\make-image.ps1
powershell -ExecutionPolicy Bypass -File out\verify-image.ps1
```

Результат сборки — один файл `unlock_v3r.efi`. Он же прошивается и он же
является откатом; якорь отката — git-тег, то есть откат равен пересборке из
исходников на этом теге (см. KNOWN-ISSUES §50).

## Структура репозитория

- `LICENSE` - полный текст GPL-2.0; `NOTICE` - происхождение кода и что здесь
  **не** распространяется
- `src/unlock_v2.c` — всё EFI-приложение (единственная сборка собирается из него);
  блок `TARGET PROFILE` в начале файла — единственное место с константами карты
- `src/build.sh` — скрипт сборки (gnu-efi, одна цель: CMP 70HX); `src/tools/` — хелперы извлечения прошивок
- `out/make-image.ps1` — сборка релизного образа флешки (MBR + FAT32 `0xEF` + загрузчик) в `dist\`
- `out/verify-image.ps1` — проверка образа: геометрия и содержимое FAT32 без монтирования; `-CompareOnly` сверяет уже записанную флешку

- **[xrip](https://github.com/xrip/cmp50hx-unlock)** —
  cmp50hx-unlock, главный вдохновитель, с которого всё началось
- **[WildFlash1st](https://github.com/WildFlash1st/cmp90hx-unlock-for-windows)** —
  cmp90hx-unlock-for-windows, на его основе строился текущий анлок
- **[bendy2](https://github.com/bendy2/cmp90hx)** — V67-эксплойт и direct-compute патч для драйвера `580.159.03` — *ключ, открывший PLM*
- **Jon Pry (Zenodo)** — *"A Canary in the Crypto Mine: Defeating Stack Protection in a GPU Secure Coprocessor"* ([DOI: 10.5281/zenodo.20916112](https://zenodo.org/records/20916112)) — раскрытие переполнения в debug-ботере
- **[cmpunlocker](https://github.com/jdowning100/cmpunlocker)** — метод rejoin16 (PLM/маски рендера) и исследования Gen2, портированные в этом проекте
- **d3dx9** — Python-эмулятор Falcon и ROP-цепочка
